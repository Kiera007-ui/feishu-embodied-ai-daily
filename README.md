# 具身智能每日推 → 飞书

## 当前架构

**Vercel Cron（每日 09:00，UTC+8） → /api/push → OpenAI Responses API + Web Search → 链接二次核验 → 飞书群自定义机器人**

同时保留原来的人工兜底链路：

**人工确认文本 → 首页转发页 → /api/send → 飞书群机器人**

自动链路不再依赖浏览器自动化、TinyFish 点击或用户打开 ChatGPT 对话。

## 自动推送流程

1. Vercel Cron 每天调用一次 `/api/push`。
2. 服务端调用 OpenAI Responses API，并要求逐一核查约定专业渠道。
3. 只保留 3–5 条符合日推标准的热点；不收论文、普通新品、常规融资和低讨论度 Demo。
4. 严格禁止新浪、网易作为最终来源。
5. 每条最终 URL 在服务端实际 GET 打开；打不开、跳到禁用域名、页面内容过薄的条目直接判失败。
6. 再调用一次模型，将“候选消息 + 实际抓取页面标题/正文”逐条做语义一致性核验。
7. 任一条链接与消息不一致时，当天任务失败并停止发送，宁可漏发也不发错链。
8. 全部通过后，服务端直接 POST 飞书 Webhook，不经过浏览器。

## 定时

`vercel.json`：

```json
{
  "path": "/api/push",
  "schedule": "0 1 * * *"
}
```

Vercel Cron 使用 UTC，`01:00 UTC = 09:00 UTC+8`。

若使用 Vercel Hobby，Cron 仍为每日一次，但可能在 09:00–09:59 之间触发；Pro/Enterprise 为分钟级。

## 环境变量

必需：

- `FEISHU_WEBHOOK_URL`：飞书群自定义机器人 Webhook。
- `OPENAI_API_KEY`：用于服务端生成和核验日推。
- `CRON_SECRET`：Vercel Cron 鉴权，建议至少 32 位随机字符串。

推荐：

- `MANUAL_SECRET`：用于 `/api/push?dry=1` 干跑检查。
- `OPENAI_MODEL`：默认 `gpt-5.6-sol`。
- `AUTO_PUSH_DISABLED=1`：紧急停用自动发送；默认不设置或设为 0。

## 状态检查

访问：

`/api/status`

仅返回自动链路是否具备所需配置，不暴露任何密钥值。

## 人工兜底

首页人工转发页和 `/api/send` 保持不变。自动链路异常时仍可使用人工确认后的冻结 Payload 发送。

## 内容口径

- 每日逐一核查：机器之心/机器之心Pro、新智元、量子位、AI前线/InfoQ、极客公园、36氪/硬氪、投资界、甲子光年、晚点、硅星人、你好太空。
- 只保留当天多方热议或刚出现、可能影响技术路线/商业判断/产业预期的内容。
- 重点关注具身模型与通用模型关系、机器人数据、真实商业化/收入/复购/ROI、触觉/末端执行、世界模型/训练、资本市场变化。
- 商业航天、物流、船舶/航运仅在当天有强消息时加入，不要求每天覆盖。
- 不收论文和纯学术研究解读。
- 不使用新浪、网易最终链接。
- 最终保持 3–5 条，宁少勿滥。

## 可靠性说明

Vercel 官方说明 Cron 失败时不会自动重试，但同一 Cron 事件偶尔可能被重复投递。因此当前架构避免任何应用层自动重试；人工补发仍保留原页面的短时间重复抑制。若后续要做到跨实例、跨小时的严格一次且仅一次，可再接入持久化 KV/Redis 锁。
